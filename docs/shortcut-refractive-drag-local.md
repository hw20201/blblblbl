# 快捷卡片折射与拾起拖动：本地修正

这次先修原生实现，没有新增库，也没有构建安装包。底稿是已发布 1.0.26/30 的准确源码 `d37c8edc6e167c8353d3abbd6d13603adfb5106e`，其父提交是已审阅实验 `7c0928490e882d9e5e0fe94a899039467006dcbf`。原草稿的版本、arm64-v8a 和签名已在此前的 APK 验证记录中对应，未发现拿错源码的证据。

## 为什么会像贴图

旧实现有几个叠加问题。颗粒强度为 0.052，按逻辑 dp 划格，接触时也存在；在高密度屏幕上，一个格子覆盖多个物理像素。新原生对照实测：同色背景的红通道跨度，旧接触状态为 13，新接触为 0，新抬起为 3。

后景重放原来只减去左上角坐标。整张卡片再缩放、倾斜时，后景也跟着变换，形成“贴在卡片上”的观感。新路径使用四角正向投影求出的二维单应变换补偿，不能用一个平移量代替。受控平移、缩放及双轴 9° 倾斜测试使用中心无折射区的参照线隔离坐标误差：旧误差约 14.78dp，新误差约 0.18dp。

原来还把卡片尺寸直接作为采样边界，越界统一 CLAMP。现在先保留 24dp 后景采样留边，再由外层统一裁切圆角，避免将被截断的边缘像素拉成一条纹。

验收还捕获了另一个真实差异：新参数 n=2 使用原生圆角矩形，阴影会把三维倾斜产生的顶点 Z 高度也算进去，形成过长的半影，影响邻近模块。新材质把平面落地阴影与三维卡面分成两层，保持原阴影参数；旧材质对照保留旧变换。没有放宽旧截图测试的 20/25px 外部保护区。新路径多一个变换层，但不新增整页截图、后景读回或第三方库。

另一个限制不在 shader：生产环境的卡片 source 只记录平滑 mesh 背景，不记录其他卡片的文字、图标或前景。渐变缺少可辨认的参照线，真实折射也会较弱。测试条纹能证明几何折射，但不能据此承诺平滑渐变会同样显眼。本轮没有给产品背景加条纹，也没有把兄弟卡片录入后景，以免引入自采样或改变现有 UI 架构。

## 这次如何验收光学效果

采用 API 35 Robolectric 原生图形渲染和 PixelCopy，不是手绘效果图。已知黑线在左边缘、上边缘发生约 2.03dp 位移；xhdpi 下约 2.01dp。中心的参照线保持不动，锐利前景区域逐像素一致。圆角外分别检查了 mdpi 853 个、xhdpi 4005 个像素，均与原后景一致。

另有真实 Dashboard 的浅色、深色 mesh 和测试专用条纹 old/new 帧。无阴影的倾斜夹具还严格核对了 74144 个卡片外采样点，全部与 source 一致，单独排除了采样留边泄漏。旧 1.0.26 shader 和参数保留为测试对照。测试条纹只存在于 `src/test`，不进入正式 app 源码。

## 拾起卡片后，手势归卡片

启用 A/B/C 手感时，从卡片按下即锁定 Dashboard 滚动并停止已有惯性滚动；越过 touch slop 后由卡片在 Initial pass 消费移动。手指离开原卡片边界也不改成页面滚动。移动范围为横向 ±24dp、纵向 ±18dp，叠加原有按压抬升和 A/B/C 动作。触点归一化扣除卡片已经移动的位移，不再锚定原槽位。原来的关闭手感选项仍走原交互。

松手、取消或多指取消会解锁页面，并弹回原位。拖动不触发导航、相邻卡片点击或 VPN 开关；正常点击和编辑排序原逻辑保留。从空白处起手仍可滚动。测试直接读取实际 ScrollState 和绘制坐标，不依赖容易陈旧的 SideEffect 快照。

## 新截图参数怎样换算

沿用网页 190px 参考高度对应原生 118dp 的比例，最后只乘一次设备 density：圆角 60 → 37.26dp；厚度 42 → 26.08dp；边缘带宽 18.5 → 11.49dp；B 配方抬升 2 → 1.24dp，阴影 12 → 7.45dp。小卡片圆角继续受半短边限制。超椭圆 2.0 使用圆角矩形，shader 与 Compose 裁切一致。

折射系数 1.60、背景距离 0.100、色散 15.5、Fresnel 0.56、边缘折射 1.20、边缘清晰度 0.70、饱和度 0.82、白色遮罩 0.10、颗粒 0.010 保留为无量纲参数。缩放 1.004、倾角 9°、回弹阻尼比 0.78 保留；A/C 的已有动作选择不改成 B。

网页“模糊 3.5”是 mip LOD，不是 Gaussian 半径 3.5px。沿用旧映射中 LOD 3 对应原生 3dp 的锚点，3.5 映射为 `3 × 2^(3.5−3) ≈ 4.24dp`。这是有限抽头的原生近似，不是跨背景分辨率严格相等的滤镜。接触时模糊和颗粒归零，抬升后才增加，边缘按清晰度减弱模糊。

保留旧原生配方的动态增益：有效光学厚度随抬升乘以 `1 + 0.55 × lift`，主位移再乘以 `1 + 0.45 × lift`。因此截图参数是基础值，不代表抬起后的每个像素与网页完全相同。这些增益及有限抽头模糊仍需真机观感确认。

采样位移和色散有边界：主位移约 9.01dp 上限，额外边缘位移有独立软饱和；色散系数缩放后为 0.31，上限 0.35。输入坐标限定在有留边的真实图层内。采样面积随留边增大，每张卡仍有滤镜成本，未进行真机 GPU、耗电或热降频测试。

## 第三方库并非只会模糊，但不能直接替换

本工程实际解析的 Compose UI 是 1.7.5，Material3 是 1.3.1；AGP 9 内建的实际 Kotlin 编译器是 2.2.10，而不是根脚本声明但未应用的 2.1.0 插件版本。compileSdk 36，minSdk 26，AGP 9.0.1，Gradle 9.6.1 均未改。

[Haze 2.0.1 的 Glass 模块](https://chrisbanes.github.io/haze/2.0.1/effects/glass/)已经提供真正折射，不应再笼统称 Haze 只能模糊。其 [Android 制品](https://repo.maven.apache.org/maven2/dev/chrisbanes/haze/haze-glass-android/2.0.1/haze-glass-android-2.0.1.aar)声明 minCompileSdk 37；发布依赖涉及 Compose 1.12.1、Kotlin stdlib 2.4.20。Glass API 仍有实验性风险，fallback 不保证折射。

[Kyant Backdrop 2.0.1](https://github.com/Kyant0/AndroidLiquidGlass/releases)的 `lens()` 也是真实 AGSL 折射，是值得优先做独立原型的备选。其 [Android 制品](https://repo.maven.apache.org/maven2/io/github/kyant0/backdrop-android/2.0.1/backdrop-android-2.0.1.aar)同样声明 minCompileSdk 37，元数据涉及 Compose Multiplatform 1.12.0、Kotlin stdlib 2.4.10。API 33 以下会跳过该 lens。

旧笔记的 [Nadeem liquid-glass 0.2.3](https://github.com/NadeemIqbal/liquid-glass)是另一个项目，目前该 Maven 坐标仍以 0.2.3 为最高版本。[Android 发布元数据](https://repo.maven.apache.org/maven2/io/github/nadeemiqbal/liquid-glass-android/0.2.3/liquid-glass-android-0.2.3.module)涉及 Compose Multiplatform 1.10.3、Material3 1.9.0 和 Kotlin stdlib 2.3.21；AAR 的 minCompileSdk 36 虽符合当前工程，也不代表可保持现有 Compose/Material3 依赖图不变。这里的 Multiplatform 版本不能直接当作最终 AndroidX 解析版本，仍须另行解析验证。

以上候选发布许可均为 Apache 2.0。共享 source 不等于每卡零成本，也不能替应用解决手势冲突。若以后考虑替换，需独立验证依赖升级、每卡离屏层、前景锐利度和真机性能。这轮没有添加、解析接入或升级任何候选库；只读取公开元数据和 AAR 的声明。

## 仍不能代替真机的部分

API 33+ 才有完整 RuntimeShader 路径；API 31/32 仍为背景柔化退化，老系统或低内存分支保持轻量。仅凭截图不能确定用户设备实际走了哪条分支；上述测量来自原生 Robolectric，而非用户手机。平滑 mesh 的肉眼可见程度、厂商驱动、低内存切换、GPU 与电池表现仍待授权后真机验收。换库同样不能绕过所有这些限制。

## 最终验证结果

完整 `:app:testDebugUnitTest` 共 313 项，0 失败、0 错误、0 跳过；Kotlin 与测试源码编译、`:app:detekt`、`:app:verifyNativeLibraries` 全部成功。原来的 `ShortcutTouchPreviewTest` 文件未修改，包含其原有严格外部像素保护区。原生库 SHA-256 校验通过。
