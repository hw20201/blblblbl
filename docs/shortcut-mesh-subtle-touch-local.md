# 本地实验：有机网格壁纸与微幅跟手

## 这次解决什么

背景原来只有少数大范围、低对比色团；在快捷卡片尺寸内，颜色变化很缓，折射即使在工作，也很难凭肉眼辨认。新版沿用全屏流动色网格方向，改成 3 列、5 行分布的 15 个有机渐变色区，适当加强明暗和色彩过渡；各区缓慢变形、游动，不会全部聚到同一角落。没有把诊断条纹或静态图片放入产品。

默认浅色保留冰蓝、淡紫的主方向，并融入当前色板的少量颜色；深色、自定义颜色仍来自原主题色板，自定义 RGB 不替换成默认蓝色。渐变刷缓存、绘制期读取共享时钟，保留原来的生命周期及减少动画控制，不让背景动画重新布局文字图标。不新增整屏高斯模糊、依赖或每卡捕获。

## 手势按最后一次要求调整

按下只给轻微视觉反馈，不再锁定页面。只有横向位移超过系统 touch-slop 的 1.25 倍，且横向位移大于纵向的 1.5 倍，才明确进入横向跟手。尚未获得横向所有权时，竖向或不够明确的斜向手势优先交给页面滚动；从卡片内部起手也能竖滑。

明确横滑后，跟手增益为 0.09，横向上限为左右各 4dp，纵向拖动为 0。获得横向所有权之后，手指的纵向漂移不再把页面带走，直到释放或取消。正常点按仍只触发原动作；空白区域仍可滚页。

纵滑让出后，先让父滚动处理 Main 阶段，再在 Final 阶段取消仍在等待的点击，防止没有滚动容器或边界情况下竖滑误触导航。事件监听因此放在 clickable 外侧，视觉变换仍在其内侧；原点击区域、语义和卡片视觉坐标不需要跟着重排。

A/B/C 选项和存储标识保留。缩放差分别约 -0.3%、+0.3%、-0.4%；倾角上限约 0.75°、1.25°、1°；默认姿态没有 Y 平移。休止投影约 0.45dp，反馈时不超过约 1.55dp。B 保留 0.78 阻尼，A/C 原本各自的回弹响应未替换。

## 为什么叠到别的卡片上仍不折射它

这不是简单的模糊度问题。现有 `cardScene` 只记录全屏壁纸，快捷卡片的标签、图标及其他前景并不在这张采样源里。上层快捷卡片因而能折射壁纸，却不能折射它没有采到的下层卡片。

测试额外强制 -80dp 位移，复现旧包的叠卡场景；这不是正常交互范围。使用零霜化的冻结姿态，并在保持上层世界坐标不变时移除下层卡片，对比上层内部像素，单独验证采样源限制，不能把它描述成已经实现层叠玻璃。

若要支持真正的卡片间折射，需要独立的共享下层合成源，明确排除主动卡片及其后代，再让主动卡片采样。不能让卡片互相读取包含自身的最终层，也不能假定 Compose 的保留层或两次 `drawContent()` 能自动解决缓存和自采样。理论上可以在空闲时不增加持续捕获，但拾起或动画期间仍有合成、采样和额外层内存成本，无法保证完全无额外 GPU 开销。本轮不冒险改造这条架构。

## 验证与边界

实际预览来自 Compose / Robolectric NATIVE / PixelCopy，包含浅色、深色、两个流动时刻、按下/微横移/释放、卡片内竖滑及强制叠卡。源码测试覆盖主题、前景锐利度、背景绘制期更新、方向阈值、滚动和动作隔离；最终数量与数值另存于验证记录。

没有真机帧时、GPU 或耗电测量。15 个缓存渐变不等于已经证明所有设备上功耗不变；更清晰的壁纸也不能替代真正的前景分层采样。原有 API 33+ 原生玻璃、API 31/32 柔化退化、较旧或低内存轻量退化策略不变。

本实验只在新的本地工作区进行，基于 `8303ebbb13b28a39f580528f7d1bfcfda07a6eb1`，不修改版本、依赖、网络/VPN、安全、MIPS 原生库、配置中心或导航动作。没有构建 APK、推送、创建 PR、创建或修改草稿。

## 最终检查结果

27 项定向检查通过；随后完整 327 项测试全部通过，失败、错误、跳过均为 0，包含新增的单指无滚动父容器防误触测试。Kotlin 主程序及测试源码编译、detekt、原生库校验通过。没有放宽截图保护区或点击/滚动断言。

实际 Dashboard 叠卡探针：下层 Profiles 图标初始有 540 个蓝色特征像素，上层覆盖后为 0；保持上层世界坐标不变并移除下层，探针区域平均 RGB 总差为 0.0。这个零霜化用例直接证明当前上层没有采样下层图标，而非图标只是被模糊掉。
